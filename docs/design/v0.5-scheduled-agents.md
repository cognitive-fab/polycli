# Scheduled agents (proposal for 0.5)

Status: design sketch, not built. Prompted by Anthropic's `launch-your-agent` repository,
where an agent is a prompt, the tools it may use, and when it runs. polycli already has
the first two per workstream (sessions with plugins, skills, MCP servers and a permission
profile); this adds the third.

## What the user gets

A workstream can hold **agents**: a name, a prompt, a schedule, and the workstream's
configuration (or a stricter permission profile of its own). Examples:

- every weekday at 08:00, *triage new GitHub issues and draft replies* (no publishing);
- every night, *run the tests, read the polywatch findings, and write a status note*;
- every Monday, *update dependencies on a branch and open a draft PR*.

Each run shows up like a session that ran by itself: in the workstream's list with its
outcome (done, failed, needs you), its answer, the files it wrote (in Artifacts), its
time and tokens. A run that hits a permission prompt it may not answer stops and lands in
the bottom bar as **needs you**, like any session.

## Where it runs

| | Local (polycli) | Cloud (Claude Code routines) |
|---|---|---|
| Runs when | polycli is open (or at sign-in, since polycli can start then) | always, on Anthropic's side |
| Sees | the workstream's folder, its env vars, local MCP servers | a fresh clone of a GitHub repository; connectors |
| Cost | the user's plan, like any session | the user's plan |
| polycli's part | schedules, launches, shows runs | creates and lists them; shows results |

Proposal: **local first**, with `claude --bg` sessions polycli already knows how to run,
watch (hooks, status line) and restart. A run is a normal session started with the agent's
prompt, named `<agent> · <date>`, closed when it ends idle. Missed runs (polycli closed)
run once at the next start, never once per missed slot. Cloud routines later, as a second
"where" for agents that must run with the PC off.

## Safety

- An agent's default profile is **Careful** (asks before publishing, pushing, deleting);
  a scheduled run can't answer asks, so it stops instead of acting. Choosing a looser
  profile for an agent is explicit and shown on the agent.
- At most one run of an agent at a time; a daily cap of runs per workstream.
- Pushes go to a branch (`agent/<name>/<date>`) and PRs are drafts; worktrees cleaned up
  by the existing Worktrees view.

## To verify first (phase 0)

1. A `--bg` session given its first prompt at launch (instead of pasted) reports state
   through the hooks as usual, and ends idle when done.
2. How a run that stops on a permission ask looks (state needs-you) and whether it can be
   picked up by the user, then finished.
3. Windows sleep and wake: timers in the main process fire after wake; catch-up rule.
4. Whether Claude Code's cloud routines can be created and listed from the CLI, to decide
   if polycli should offer them or only link to them.

## Data

`state.agents[]`: `{ id, workstreamId, name, prompt, schedule: { kind: 'daily'|'weekly'|'interval', at, days, every }, profile, model, effort, enabled, lastRun, nextRun }`;
runs as sessions with `agentId`, so existing views (time, tokens, artifacts, findings)
work for them unchanged.
